# 웹 검색으로 확인한 종가 수동 입력

`manual.yml`은 8종목 가격과 `price_dates` JSON을 모두 받습니다. 종가와 기준일을
각각 확인한 뒤 입력하세요. 하나라도 확인하지 못하면 실행하지 않습니다.
`update.yml`의 자동 수집을 활성화하거나 실행하지 않습니다.

- `trade_date`: 한국시간 순위 스냅샷 날짜. `history.day`와 주간 차트의 날짜입니다.
- `price_dates`: 종목별 실제 종가 기준일. `prices.markets[시세 코드].date`와 새 기록의
  `history.priceDates`에 저장합니다. 미국 주식은 해당 거래소 거래일, 업비트 BTC는
  완료된 일봉의 시작 날짜(UTC 00:00 / KST 09:00), 한국 주식은 해당 거래일입니다.
- `updatedAt`: 코드가 데이터를 저장한 실제 한국시간. 사이트 상단 갱신 시각입니다.
  실제 Pages 게시 시각은 배포 완료 후 사이트에서 별도로 확인하세요.

날짜 형식 예시(실제 실행 시에는 각 종목을 검증한 날짜로 바꿉니다):

```json
{"NVDA":"2026-10-12","TSLA":"2026-10-12","AMZN":"2026-10-12","GOOGL":"2026-10-12","KRW-BTC":"2026-10-12","034020.KS":"2026-10-13","267260.KS":"2026-10-13","011200.KS":"2026-10-13"}
```

키 8개와 날짜·양수 가격을 모두 검증하며 날짜 누락을 공통 날짜로 채우지 않습니다.
기존 기록의 종가 날짜를 추정하여 추가하거나 고치지 않습니다. 가격과 종가 기준일이
모두 같으면 JSON·갱신 시각·기록을 보존하고 커밋과 배포를 생략합니다.
예약 작업도 기존 `data/prices.json`과 비교하여 변화가 없으면 워크플로를 호출하지
않아야 합니다. 동일 입력 환경변수로 `python scripts/manual_update.py --check`를
실행하면 파일 쓰기 없이 입력과 변경 여부를 확인할 수 있습니다.

수동 워크플로는 `main`에서만 동작하며 기존 `github-pages` 배포 환경을 사용합니다.
새 입력 `price_dates`를 제공하지 않는 기존 호출은 실패하므로 예약 호출도 이에
맞춰야 합니다. 로컬 검증은 `python -m unittest discover -s tests -v`로 실행합니다.
Node.js가 있으면 실제 프런트 코드로 순위·주간 차트 호환성도 검사합니다.
